## Five-discipline assessment

**Code:** no API, solver or state-machine source was sampled, so correctness remains unverified despite extensive tree inventory. **Automation:** CI describes typecheck, lint, coverage and Redis integration, but pass results are historical. **Operations:** staging and production workflows exist; host credentials, TLS, registry, digest promotion, backups and recovery are not observed. **Security:** inspect API authentication and per-resource authorization, command injection in solver/LaTeX invocation, SSRF in literature calls, secret handling and bundle canaries, dependency integrity and evidence data retention. These are risks to investigate, not asserted exploits. **UI/UX:** landing, dashboard and video are separate products; fixture/live mode labels, accessible charts and keyboard behavior require browser verification.

## Production blockers and questions

Who owns scientific validation, real SU2 execution, credentials, production environment approvals, evidence retention and release provenance/attestation acceptance? Who controls GitHub environment reviewers, the digest-promotion policy, restore-drill signoff and production release acceptance? What is the authoritative trace from computation to manuscript? Verify release identity and recovery before any production deployment; do not equate tests with scientific certification.
